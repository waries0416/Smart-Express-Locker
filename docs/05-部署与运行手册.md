## 1. 文档说明

本文分两部分：

- **第 2~6 章：从零部署**。一台没装过本项目的机器，按顺序执行即可。

## 2. 环境要求

### 2.1 软件

| 组件 | 版本要求 | 检查命令 | 说明 |
|---|---|---|---|
| Python | ≥ 3.10（实测 3.13.5） | `python -V` | 需带 `venv` 与 `pip` |
| MySQL | ≥ 8.0（实测 8.0.39） | `mysql --version` | 必须 8.0+，项目用了 CHECK 约束与 `utf8mb4_0900_ai_ci` |
| 浏览器 | Chrome / Edge 近两年版本 | — | 触屏端与管理端 |
| 手机 | iOS Safari / Android Chrome | — | 手机端 H5 |
| cloudflared | 最新版（可选） | `cloudflared --version` | 仅"手机在外网扫码"时需要 |

> MySQL 5.7 **不可用**：`CHECK` 约束在 5.7 中被静默忽略，项目依赖它守住 36 条业务规则（如 `expire_time > store_time`、`pickup_code` 必须 6 位数字）。

### 2.2 硬件与网络

| 项 | 最低 | 建议 |
|---|---|---|
| CPU / 内存 | 2 核 / 4 GB | 4 核 / 8 GB |
| 磁盘 | 2 GB 可用 | 10 GB |
| 网络 | 本机回环即可 | 手机端需与本机同一局域网；跨网段需隧道 |

### 2.3 端口

| 端口 | 用途 | 可改 |
|---|---|---|
| 5000 | Flask 服务 | 是，环境变量 `PORT` |
| 3306 | MySQL | 是，环境变量 `DB_PORT` |

## 3. 从零部署（五步）

### 第 1 步：准备代码

把项目放到任意目录，本文以 `D:\SoftwareEngineering` 为例。目录结构应如下：

│   ├── app.py               # 入口
│   ├── auth.py              # 认证与会话

│   ├── entities.py          # 实体 CRUD
│   ├── mobile_api.py        # 手机端接口
│   ├── notify.py            # 通知入队与投递
│   ├── qr_login.py          # 扫码登录票据

│   ├── db.py                # 数据访问封装

### 第 2 步：Python 环境

```bash
cd D:\SoftwareEngineering

python -m venv .venv
.venv\Scripts\python.exe -m pip install -U pip
.venv\Scripts\pip.exe install -r backend\requirements.txt
```

依赖只有四个：

| 包 | 用途 |
|---|---|
| `flask` | Web 框架 |
| `pymysql` | MySQL 驱动 |
| `DBUtils` | 连接池（`PooledDB`） |
| `segno` | 服务端生成二维码 SVG（纯 Python，不需要 Pillow） |

**验证**：

```bash
.venv\Scripts\python.exe -c "import flask, pymysql, dbutils, segno; print('deps ok')"
```

预期输出 `deps ok`。

### 第 3 步：初始化数据库

这一步最容易出错，务必按顺序执行**两个**脚本。

```bash
# 3.1 建库 + 建表 + 导入种子数据（会先 DROP DATABASE，重复执行即重置）
mysql -u root -p < init_database.sql

# 3.2 建视图 / 触发器 / 存储过程（init_database.sql 里没有，必须单独执行）
mysql -u root -p smart_locker < db\objects.sql
```

> **为什么必须两个脚本？**
> `init_database.sql` 只含表结构（DDL）与数据（DML），由导出工具生成；视图、触发器和存储过程放在 `db/objects.sql`。
> 少了第 2 步会出两个症状：① 接口报"表或视图不存在"（`v_package_detail` 缺失）；② 取件后格口不释放（触发器 `trg_package_after_update` 缺失），格口会一直显示"占用"。

**验证**：

```bash
mysql -u root -p smart_locker -e "
  SELECT COUNT(*) AS tables_ FROM information_schema.tables
   WHERE table_schema='smart_locker' AND table_type='BASE TABLE';
  SELECT COUNT(*) AS views_ FROM information_schema.views
   WHERE table_schema='smart_locker';
  SELECT COUNT(*) AS triggers_ FROM information_schema.triggers
   WHERE trigger_schema='smart_locker';
  SELECT COUNT(*) AS procs_ FROM information_schema.routines
   WHERE routine_schema='smart_locker';"
```

预期：`tables_=12`、`views_=2`、`triggers_=1`、`procs_=3`。

再看种子数据量：

```bash
mysql -u root -p smart_locker -e "
  SELECT (SELECT COUNT(*) FROM t_cabinet)  AS cabinets,
         (SELECT COUNT(*) FROM t_cell)     AS cells,
         (SELECT COUNT(*) FROM t_user)     AS users,
         (SELECT COUNT(*) FROM t_package)  AS packages;"
```

预期：`30 / 720 / 122 / 312`。

#### 已有库的增量升级

如果是**已经跑过旧版本**的库，不要重跑 `init_database.sql`（会清空数据），改按顺序执行迁移：

```bash
mysql -u root -p smart_locker < db\migrations\001_mobile.sql    # 手机端所需字段/表
mysql -u root -p smart_locker < db\migrations\002_qr_login.sql  # 扫码登录票据 t_qr_ticket
```

两个迁移脚本都是幂等的（`CREATE TABLE IF NOT EXISTS` / 条件加列），重复执行安全。

### 第 4 步：配置数据库连接

默认配置在 `config.py`，**优先读环境变量**，因此生产环境不必改代码：

```python
DB_CONFIG = {
    "host":     os.getenv("DB_HOST", "127.0.0.1"),
    "port":     int(os.getenv("DB_PORT", "3306")),
    "user":     os.getenv("DB_USER", "root"),
    "password": os.getenv("DB_PASSWORD", "123456"),
    "database": os.getenv("DB_NAME", "smart_locker"),
    ...
}
```

三种改法，任选其一：

| 方式 | 操作 | 适用 |
|---|---|---|
| 改默认值 | 直接编辑 `config.py` 里的默认字符串 | 本机自用 |
| 临时环境变量 | `set DB_PASSWORD=你的密码`（cmd） | 单次调试 |
| 永久环境变量 | 系统属性 → 环境变量 → 新建 `DB_PASSWORD` | 服务器部署 |

**验证**：

```bash
.venv\Scripts\python.exe -c "import sys;sys.path.insert(0,'backend');import db;print(db.query_one('SELECT VERSION() v'))"
```

预期输出形如 `{'v': '8.0.39'}`。报 `Access denied` 就是密码不对；报 `Unknown database` 就是第 3 步没做。

## 4. 三种启动方式

### 4.1 方式一：本地一键启动（默认，最常用）

```bash
scripts\start.bat
```

做的事：切到项目根 → 优先用 `.venv` 的 Python（找不到则退回系统 Python）→ 读 `PORT`（默认 5000）→ 打印三端地址与演示账号 → 启动 Flask。

适用：本机演示、答辩现场、局域网内手机访问。

### 4.2 方式二：直接跑入口文件

```bash
.venv\Scripts\python.exe backend\app.py
```

适用：需要自定义环境变量时，例如：

```bash
set PORT=8080
set NOTIFY_WORKER=0
.venv\Scripts\python.exe backend\app.py
```

`NOTIFY_WORKER=0` 会关掉后台通知轮询线程，测试脚本导入应用时用它避免干扰。

### 4.3 方式三：带内网穿透（手机在外网也能扫码）

```bash
scripts\start-with-tunnel.bat
```

做的事：

1. 启动 Flask（后台进程）；
2. 轮询 `/api/health` 直到服务就绪；
3. 启动 `cloudflared tunnel --url http://127.0.0.1:5000`；
4. 从 cloudflared 输出里抓取 `https://xxx.trycloudflare.com`，写入 `logs/public_base_url.txt`；
5. Flask **无需重启**——`/api/m/base-url` 每次请求都重读该文件，二维码里的深链立刻变成公网地址。

只想要服务、不要隧道：`scripts\start-with-tunnel.bat -NoTunnel`。

**为什么需要隧道？** 手机端要能打开柜机屏上的二维码深链，就必须有一个手机可达的地址。局域网 IP 在校园网 AP 隔离下常常不通；`getUserMedia`（网页调摄像头）又只在 HTTPS 下可用。用临时 HTTPS 域名一次解决这两个问题。

**验证**：

```bash
curl http://127.0.0.1:5000/api/m/base-url
```

- 有隧道时：`{"base_url":"https://xxx.trycloudflare.com","source":"tunnel"}`
- 无隧道时：`{"base_url":"http://192.168.x.x:5000","source":"auto"}`

**停止**：在启动窗口按 `Ctrl+C`；隧道方式下脚本会一并结束 cloudflared 子进程。

## 5. 访问地址与演示账号

| 端 | 地址 | 说明 |
|---|---|---|
| 触屏端（柜机） | `http://127.0.0.1:5000/` | 默认首页，也是 `/kiosk` |
| 管理端 | `http://127.0.0.1:5000/admin` | 未登录会 302 到 `/admin/login` |
| 手机端 H5 | `http://127.0.0.1:5000/m` | 手机访问需把 `127.0.0.1` 换成本机局域网 IP |

### 5.1 账号

| 角色 | 入口 | 账号 | 口令 |
|---|---|---|---|
| 管理员 | 管理端 | `admin` | `admin123` |
| 用户 | 触屏端扫码 / 手机端 | 手机号 `15800000001` | 短信验证码（见下） |
| 快递员 | 触屏端底部按钮 / 手机端切换 | 工号 `E00001` + 手机号 `13900000001` | 无 |

管理员账号定义在 `backend/auth.py` 的 `ADMIN_ACCOUNTS` 字典里，可自行增删。

### 5.2 手机端验证码怎么拿

课程设计不接真实短信通道，验证码走**开发模式回传**：

```bash
curl -X POST http://127.0.0.1:5000/api/m/auth/send-code \
     -H "Content-Type: application/json" -d "{\"phone\":\"15800000001\"}"
```

响应里的 `dev_code` 就是验证码：

```json
{"message":"验证码已发送","expire_in":300,"dev_code":"483920"}
```

规则：5 分钟有效，同一手机号 60 秒内只能发一次（防轰炸）。

接真实短信后置 `MOBILE_DEV_MODE=0`，`dev_code` 不再回传，只写日志。

### 5.3 演示数据

反复演示后包裹会被取走，"待取列表"变空。一条命令复原：

```bash
.venv\Scripts\python.exe scripts\reset_demo_data.py
```

可选参数：

| 参数 | 默认 | 含义 |
|---|---|---|
| `--phone` | `15800000001` | 操作哪个账号名下的包裹 |
| `--stored` | `2` | 希望保留几件正常待取 |
| `--keep-expired` | `1` | 希望保留几件超时未缴费 |
| `--clean` | 关 | 顺带清理验证码、柜机指令、失效票据 |

安全边界：只动指定手机号的数据；只把"超时且从未取件"的包裹改回待取，**不碰已取件记录**，避免出现"已取件却还在柜里"的矛盾数据。

复原后 `15800000001` 名下应有：

| 柜体 | 格口 | 取件码 | 状态 |
|---|---|---|---|
| CAB-001 | B05 | 549548 | 待取 |
| CAB-001 | A01 | 878905 | 待取 |
| CAB-001 | C05 | 782116 | 超时待缴 ¥1.00 |

## 6. 配置项全表

全部通过环境变量注入，改完重启生效（`PUBLIC_BASE_URL` 除外，见 4.3）。

| 变量 | 默认 | 作用 |
|---|---|---|
| `PORT` | `5000` | Flask 监听端口 |
| `ADMIN_PATH` | `admin` | 管理端 URL 前缀（改成 `mgmt` 则后台在 `/mgmt`） |
| `DB_HOST` | `127.0.0.1` | MySQL 地址 |
| `DB_PORT` | `3306` | MySQL 端口 |
| `DB_USER` | `root` | 数据库账号 |
| `DB_PASSWORD` | `123456` | 数据库口令 |
| `DB_NAME` | `smart_locker` | 库名 |
| `DB_POOL_MAX` | `10` | 连接池上限（并发上限的硬约束） |
| `DB_POOL_MIN` | `1` | 池内常驻连接数 |
| `DB_POOL_CACHED` | `5` | 空闲时最多缓存几条 |
| `PUBLIC_BASE_URL` | 空 | 手机端深链的固定公网地址（优先级最高） |
| `MOBILE_DEV_MODE` | `1` | `1` 时验证码回传 `dev_code`，仅演示用 |
| `NOTIFY_ENABLED` | `1` | 通知总开关，`0` 则入队直接返回 |
| `NOTIFY_WORKER` | `1` | `0` 则不启动后台投递线程 |
| `NOTIFY_WORKER_INTERVAL` | `15` | 投递线程轮询间隔（秒） |
| `NOTIFY_BATCH_SIZE` | `50` | 每轮最多投递条数 |
| `NOTIFY_MAX_RETRY` | `3` | 单条最多重试次数 |
| `NOTIFY_CHANNELS` | `SMS,INBOX,PUSH` | 启用渠道（逗号分隔） |
| `NOTIFY_SMS_PROVIDER` | `mock` | 短信渠道实现，`mock` 只写日志 |
| `NOTIFY_REMIND_BEFORE_HOURS` | `6` | 到期前几小时发提醒 |
| `NOTIFY_FAIL_RATE` | `0` | 模拟失败概率，用于演示重试退避 |
| `NOTIFY_LOG` | `logs/notify.log` | 通知日志路径 |

**优先级**（手机端深链地址）：`PUBLIC_BASE_URL` 环境变量 → `logs/public_base_url.txt`（隧道写入）→ 本机局域网 IP。

## 7. 数据库运维

### 7.1 备份

```bash
mysqldump -u root -p --single-transaction --routines --triggers smart_locker > backup_%date%.sql
```

必须带 `--routines --triggers`，否则视图之外的存储过程与触发器会丢。

### 7.2 恢复

```bash
mysql -u root -p smart_locker < backup_20261117.sql
```

### 7.3 完整重置（回到出厂状态）

```bash
mysql -u root -p < init_database.sql
mysql -u root -p smart_locker < db\objects.sql
```

`init_database.sql` 开头就是 `DROP DATABASE IF EXISTS smart_locker`，执行即清空。**执行前先备份**。

### 7.4 检查约束是否生效

```bash
mysql -u root -p smart_locker -e "
  SELECT COUNT(*) AS checks_ FROM information_schema.check_constraints
   WHERE constraint_schema='smart_locker';"
```

预期 `checks_=36`。如果只有个位数，说明 MySQL 版本过低（5.7 会静默忽略 CHECK）。

### 7.5 手工验证触发器

取一件包裹后，格口应自动释放。若怀疑触发器没建：

```bash
mysql -u root -p smart_locker -e "SHOW TRIGGERS\G" | grep trg_package_after_update
```

没有输出就回去执行 `db/objects.sql`。

### 8.1 健康检查

```bash
curl http://127.0.0.1:5000/api/health
```

| 返回 | 含义 |
|---|---|
| `{"status":"ok","db":"connected"}` | 正常 |
| `{"status":"error","db":"..."}` + 500 | 数据库不可用，`db` 字段是原始异常 |

生产环境建议每 30 秒探一次，连续 3 次失败告警。

```bash
curl "http://127.0.0.1:5000/api/notify/stats"
```

手动触发一轮（演示时不想等 15 秒）：

```bash
curl -X POST http://127.0.0.1:5000/api/notify/dispatch
```

## 9. 故障排查

| 现象 | 最可能原因 | 处置 |
|---|---|---|
| 启动报 `ModuleNotFoundError: No module named 'dbutils'` | 用了系统 Python 而不是 `.venv` | 显式用 `.venv\Scripts\python.exe`；或 `pip install DBUtils` |
| 启动报 `Access denied for user 'root'@'localhost'` | 数据库口令不对 | 设 `DB_PASSWORD` 环境变量，或改 `config.py` 默认值 |
| 启动报 `Unknown database 'smart_locker'` | 没跑 `init_database.sql` | 执行第 3 步 |
| 接口报 `Table 'smart_locker.v_package_detail' doesn't exist` | 只跑了建表脚本，没跑 `db/objects.sql` | 补执行 `db/objects.sql` |
| 取件成功但格口一直显示"占用" | 触发器缺失 | 同上，补 `db/objects.sql` |
| `Address already in use`（端口占用） | 5000 已被占用（常见于上次没退干净） | `netstat -ano \| findstr :5000` 找到 PID，`taskkill /PID <pid> /F`；或 `set PORT=5001` |
| 中文全是乱码 | 客户端字符集不是 utf8mb4 | 库与连接串都已固定 `utf8mb4`；确认终端用 UTF-8 编码（cmd 先 `chcp 65001`） |
| 时间显示差 8 小时 | 手机端 `fmtTime` 对 RFC 串按 UTC 还原，数据库存的是本地时间 | 统一让 MySQL 与会话时区一致：`SET time_zone='+08:00'` |
| 手机扫二维码打不开 | 深链是局域网 IP，手机不在同一网段 | 改用 `start-with-tunnel.bat`，或设 `PUBLIC_BASE_URL` 为自己的公网域名 |
| 手机扫二维码能开但摄像头用不了 | `getUserMedia` 需 HTTPS | 本系统已不依赖网页摄像头：柜机出码、手机系统相机扫 |
| `start-with-tunnel.ps1` 报"字符串缺少终止符" | PowerShell 5.1 读无 BOM 的 UTF-8 中文脚本会乱码 | 脚本已按 `UTF-8 with BOM + CRLF` 保存，勿用其他编辑器另存为无 BOM |
| 隧道启动报"已添加了具有相同键的项" | 环境里同时存在 `HTTPS_PROXY` 与 `https_proxy` | 脚本开头已清理 4 个小写代理变量；如仍报，手工 `set https_proxy=` 后重试 |
| 通知一直 `PENDING` | `NOTIFY_WORKER=0` 或线程异常退出 | 去掉该变量重启；或手动 `POST /api/notify/dispatch` |
| 后台登录后刷新又回登录页 | Cookie 被浏览器拦截（非同源 / 无 `SameSite`） | 用 `127.0.0.1` 而非 `localhost` 与 IP 混用访问 |
| 触屏端显示的还是旧页面 | 浏览器缓存 | 服务端已对 HTML 下发 `no-store`；仍出现则强制刷新 `Ctrl+F5`，并确认没连到旧进程 |

## 10. 生产化部署参考（非课程设计必需）

课程设计要求本机可运行即可。若要真放到服务器上，建议：

### 10.1 用 WSGI 服务器替代 Flask 内置

Flask 自带的开发服务器单线程、无进程管理，不能上生产。

```bash
pip install waitress
waitress-serve --listen=0.0.0.0:5000 --threads=8 backend.app:app
```

Windows 用 `waitress`，Linux 用 `gunicorn`：

```bash
gunicorn -w 4 -b 0.0.0.0:5000 --timeout 60 backend.app:app
```

> 注意：`backend/app.py` 里 `if __name__ == "__main__"` 之外的部分才是应用本体，WSGI 入口是模块级的 `app` 对象，导入即可，不需要跑 `app.run()`。

### 10.2 反向代理与 HTTPS

```nginx
server {
    listen 443 ssl;
    server_name locker.example.com;

    ssl_certificate     /etc/ssl/locker.crt;
    ssl_certificate_key /etc/ssl/locker.key;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

有了固定 HTTPS 域名，就不需要 cloudflared，直接：

```bash
set PUBLIC_BASE_URL=https://locker.example.com
```

### 10.3 服务化

Windows 用 `nssm`，Linux 用 `systemd`：

```ini
[Unit]
Description=Smart Locker
After=network.target mysql.service

[Service]
WorkingDirectory=/opt/softeng
Environment=DB_PASSWORD=****** PUBLIC_BASE_URL=https://locker.example.com
ExecStart=/opt/softeng/.venv/bin/gunicorn -w 4 -b 127.0.0.1:5000 backend.app:app
Restart=always

[Install]
WantedBy=multi-user.target
```

### 10.4 上线前必改项

| 项 | 现值 | 改成 |

| `MOBILE_DEV_MODE` | `1`（回传验证码） | `0` |

| `DB_PASSWORD` | `123456` | 强口令，且只授予本库权限 |
