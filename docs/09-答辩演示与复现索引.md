## 1. 环境准备（答辩前 15 分钟做完）

### 1.1 硬性前置检查（**先查这个，再查代码**）

`db/objects.sql` 不是可选项。缺了它，详情接口 500、取件后格口不释放。

**首选检查（一条命令，权威）**：

```bash
# 期望末尾输出 [verify] 全部通过（格式是“每表行数表 + 结论行”，不是三行摘要）
python scripts/init_db.py --verify
```

**辅助检查（只读查询，需要 mysql 客户端）**：

```bash
mysql -uroot -p smart_locker -e "
  SELECT (SELECT COUNT(*) FROM information_schema.VIEWS
           WHERE TABLE_SCHEMA='smart_locker')     AS views_,      -- 期望 2
         (SELECT COUNT(*) FROM information_schema.TRIGGERS
           WHERE TRIGGER_SCHEMA='smart_locker')   AS triggers_,   -- 期望 1
         (SELECT COUNT(*) FROM information_schema.ROUTINES
           WHERE ROUTINE_SCHEMA='smart_locker')   AS procs_;      -- 期望 3
"
```

| 结果 | 处理 |
|---|---|
| `2 / 1 / 3` | 通过，继续 |
| `views_ = 0` | 执行 `python scripts/init_db.py --migrate`（幂等补齐对象） |
| `triggers_ = 0` | 同上；否则取件后格口永远显示"占用"。**不要用 `mysql < db/objects.sql`**，见 §3.1 |

期望表数量与关键行数：

```bash
mysql -uroot -p smart_locker -e "
  SELECT COUNT(*) AS tables_ FROM information_schema.tables
   WHERE table_schema='smart_locker' AND table_type='BASE TABLE';   -- 期望 20
  SELECT (SELECT COUNT(*) FROM t_cabinet) AS cabinets,               -- 期望 30
         (SELECT COUNT(*) FROM t_cell)    AS cells,                  -- 期望 720
         (SELECT COUNT(*) FROM t_user)    AS users,                  -- 期望 120
         (SELECT COUNT(*) FROM t_package) AS packages;               -- 期望 310
"
```

> 若行数与此不同：先确认没有别人正在跑测试或重置脚本（多人共用一套库时会漂），再跑
> `python scripts/reset_demo_data.py --clean` 复原演示数据。

### 3.1 单元测试的前置条件（很重要）

测试必须在**视图与触发器已建**的库上跑。缺触发器时会出现：

```
FAIL: test_pickup_succeeds_after_payment
AssertionError: 'OCCUPIED' != 'FREE'
```

这不是代码 bug，是环境缺 `db/objects.sql`。先按 §1.1 跑 `python scripts/init_db.py --verify`。

> **为什么不能 `mysql < db\objects.sql`。** `db/objects.sql` 里的
> `CREATE TRIGGER ... BEGIN ... END;` 是复合语句，MySQL 命令行客户端默认以分号切分，
> 遇到 `BEGIN` 内部的 `;` 就提前截断 → `ERROR 1064`。**这不是"少了 `/*OBJECTS_SPLIT*/` 标记"的问题**，
> 标记只是给脚本切分用的便利声明，命令行客户端根本不看它。
> 正确做法是走 `scripts/init_db.py`，它在 Python 侧识别复合语句边界后逐条 `execute()` 提交。

另外，`test_route_separation` 会真的往 `t_express_company` 插一行 `ZZTEST` 再删掉。
若上一次跑的进程被强杀，残留行会导致下次 `AssertionError: 400 != 201`（唯一键冲突）。
现在由 `backend/tests/_fixtures.purge_residue()` 在每轮开跑前幂等预清理；手工清理用：`DELETE FROM t_express_company WHERE company_code LIKE 'ZZTEST%';`

## 4. 常见故障排查

| 症状 | 原因 | 处理 |
|---|---|---|
| `GET /api/packages/<id>/detail` 返回 500，日志 `Table 'smart_locker.v_package_detail' doesn't exist` | 没跑 `db/objects.sql` | 执行 `python scripts/init_db.py --migrate`（幂等补齐对象） |
| 取件成功但格口仍显示"占用" | 触发器 `trg_package_after_update` 缺失 | 同上 |
| 单元测试 `'OCCUPIED' != 'FREE'` | 同上 | 同上 |
| 单元测试 `400 != 201`，且是 `test_entity_mutation_allowed_with_admin` | 上次残留 `ZZTEST` 公司行 | `DELETE FROM t_express_company WHERE company_code='ZZTEST';` |
| 存件返回 409「当前无可用格口」 | 该柜体该规格格口被占满（演示反复存件后常见） | 换柜体或换规格；或重置数据库 |
| 手机端登录拿到验证码但登录 401 | 验证码超 5 分钟，或 60 秒内重复发送 | 重新 `send-code` 取新的 `dev_code` |
| 手机扫码后柜机不跳转 | 柜机与手机不同网段（AP 隔离） | 用 `scripts\start-with-tunnel.bat` 起内网穿透；或确认手机与电脑同 Wi-Fi |
| 手机端页面长时间空白 | 把 `127.0.0.1` 当成了手机可访问地址 | 改用电脑局域网 IP（`ipconfig` 查看），或看 `/api/m/base-url` 返回的地址 |
| 管理端登录后刷新又回到登录页 | Cookie 被清，或 `AUTH_SECRET` 在重启后变了 | 重新登录；固定 `AUTH_SECRET` 环境变量 |
| `mysql` 命令找不到 | 未把 MySQL `bin` 加进 PATH | 用绝对路径 `"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe"` |
| `python` 命令打开应用商店 | 本机 `python` 是 Store 占位符 | 用虚拟环境 `.venv\Scripts\python.exe`，或显式指定 Python 解释器路径 |
